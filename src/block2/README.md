# Block 2 — Recurrent Binary Network (Fig. 2 reproduction)

Reproduces Block 2 of Renart et al. 2010, *The Asynchronous State in Cortical Circuits*
(*Science* 327): the analytically tractable recurrent binary network behind main-text Fig. 2.
This is where the `r̄ ~ 1/N` scaling, the E/I tracking relations, and the current-correlation
cancellation are *derived*, not just observed — Block 1 built the intuition (shared input vs.
correlated input) at the smallest possible scale; Block 2 shows the same cancellation emerges
*spontaneously* from a full recurrent network's own dynamics.

## The network

Three populations of equal size `N` — excitatory `E`, inhibitory `I`, and an external
population `X` of `N` cells that receives no recurrent input — under **Glauber dynamics**:
binary state `σ_i^α(t) ∈ {0,1}`, updated one neuron at a time. Connectivity is **dense**
(`p=0.2` fixed regardless of `N`) and **strong** (synaptic weights scale as `1/√N`, S-Eq 1),
so each cell's afferent current (S-Eq 7) is

```
h_i^α = Σ_β (J^{αβ} · σ^β)_i − θ        α ∈ {E,I}, β ∈ {E,I,X}
```

**The exact simulation algorithm** (S-p.18, the thing that actually gets implemented): pick
one of the `3N` neurons uniformly at random; if it's in `X`, redraw it fresh from
Bernoulli(`m_X`); otherwise set it deterministically to `Θ(h_i^α)`. `3N` such picks define one
neuronal time constant `τ`, so `dt = τ/(3N)` — temporal resolution improves with `N`
automatically. This makes the model fundamentally different from Block 1/3's continuous-time
LIF networks: no ODE, no spike event, just a discrete Monte Carlo pick — which is why block 2
is NumPy/Numba-native rather than Brian2 (`docs/adr/0003`).

## The input

`X`'s cells have no recurrent input at all — each one is simply an independent Bernoulli(`m_X`)
coin flip every time it's picked, with no memory of its own previous state. `m_X = 0.1`
throughout. This is the network's only external drive; everything else (the `E`/`I` dynamics,
the tracking, the cancellation) is generated by the recurrent connectivity itself.

## The output — what's measured

- **`r̄`** — population-averaged pairwise firing correlation: plain Pearson correlation of two
  cells' raw sampled binary strings (no windowing needed at `SR=1`, unlike Block 1/3's
  windowed-rate `r_out` — S-p.19 vs. S-Eq 34-37). `eval.population_averaged_correlation`.
- **`c` / `c_EE` / `c_II` / `c_EI`** — the same correlation, but of cells' *current* `h_i`
  instead of their binary state (S-Eq 32-33): `c = c_EE + c_II + 2c_EI ~ 1/√N`, while
  `r̄ ~ 1/N` — the paper's central asynchronous-state claim.
- **CCGs** — the lag-dependent version of the above (`eval.population_averaged_ccg`), used for
  Fig. 2E's current-component cross-correlograms.

## Objectives — what we're looking for

- **Fig. 2B** — one cell's current components (`E`/`I`/`X`/`Total`) over time: the "dynamic
  balance" `Total` should hover near the dashed threshold while its `E`/`X`/`I` components sit
  far from it individually.
- **Fig. 2C** — `r̄`, `c`, `c_EE`, `c_II`, `c_EI` vs. `N` on a log-log plot: `r̄` should fall
  along `~1/N`, `c` along `~1/√N`, while the components stay `O(1)`.
- **Fig. 2D** — z-scored population activity `m_E(t)`/`m_I(t)`/`m_X(t)` at `N=1024` and
  `N=8192`: `I` should visibly track `E` with a small, `N`-shrinking lag.
- **Fig. 2E** — current-component CCGs at `N=8192`: peaked near zero lag, narrowing/shrinking
  with `N` (the same EI-lag as 2D, seen in the frequency/lag domain).
- **Fig. 2G** — histogram of `r` over EE pairs at `N=8192`: wide and centered near zero
  (`σ_r ≫ r̄`), not a tight spike at the ensemble mean from 2C.

## Module map

The core model (small, always used) vs. the production/reproduction machinery (bigger, only
used to actually generate Fig. 2's numbers) are kept in separate files:

| File | Role |
|---|---|
| `connectivity.py` | `build_weights` — S-Eq(1) connectivity, one dense per-realisation call |
| `model.py` | `afferent_current`/`tick` — the reference (pure-Python, single-realisation) implementation of S-Eq 5-7's exact algorithm; the correctness oracle everything else is checked against |
| `simulate.py` | `simulate` — loops `model.tick` over realisations + burn-in/sampling; used at exploratory scale, too slow for production (`docs/adr/0003`) |
| `theory.py` | `predicted_rates` — S-Eq(18)'s closed-form population-rate prediction, independent of the simulation, used to validate it |
| `eval.py` | `population_averaged_correlation`/`population_averaged_ccg` — the shared correlation/CCG math every panel's analysis reuses |
| `exploratory_pass.py` | Small-`N` validation run (`config.yaml: binary_network.exploratory`) checked against `theory.py` — not reproduction numbers. `python -m block2.exploratory_pass` |
| `fast_model.py` | Numba-JIT'd versions of `model.py`'s algorithm (`simulate_fast`, `simulate_fast_one`, `simulate_fast_current`) — what production-scale (`N` up to 8192) runs actually use |
| `parallel.py` | `simulate_fast_parallel` — realisation-batched multiprocessing; superseded by Slurm for the real full pass (ARM64 `ProcessPoolExecutor` instability, `docs/adr/0003`), kept for smaller/local parallel use |
| `panel_traces.py` | Cheap single-realisation JIT recordings for the illustrative panels (2B's cell components, 2D's population mean, 2G's neuron subsample) — distinct from the summary-statistics sweeps below |
| `full_pass.py` + `full_pass.slurm` | **Fig. 2C's `r̄` sweep.** One Slurm array task per `(N, realisation)`, each a single independent process (not Python multiprocessing) writing its own summary row. `python -m block2.full_pass <task_index>`, then `--aggregate` |
| `full_pass_current.py` + `full_pass_current.slurm` | **Fig. 2C's `c`/`c_EE`/`c_II`/`c_EI` sweep** — same shape as `full_pass.py`, over a subsampled current recording instead of full population state |
| `illustrative_panels.py` | Generates 2B/2D/2E/2G's raw CSVs from `panel_traces.py`'s recordings — short, cheap, qualitative-shape runs, no DGX needed. `python -m block2.illustrative_panels {b,d,e,g}` |
| `plot_fig2.py` | All five Fig. 2 plots, paper's own color code (E green / I red / X blue / Total black) |
